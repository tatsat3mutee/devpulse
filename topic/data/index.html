Postgres SELECT DISTINCT scans every matching row despite indexes

In a Postgres-backed queue workload, SELECT DISTINCT became the most expensive query because it scans every row matching the predicates, even when few unique values are needed. The explanation of the database's design trade-offs and workarounds can inform high-volume query design.

  • WhatPostgres SELECT DISTINCT scans every row matching its predicates, even with an index and few distinct values to return.
  • HowIn a partitioned-queue workload, the query slowed on deep partitions; latency grew linearly with rows per partition.
  • Why it mattersEngineers should check query plans rather than assume indexed deduplication scales with unique results; simple queue queries can dominate workload cost.
